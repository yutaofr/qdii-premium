## P1 · 方向推论：符号本身算反了

**接受，且原推导有错。** f237d46 写"隔夜基差收窄 → `F(t)/F(c)` 略微高估指数涨幅 → 估算净值略偏高 → 估算溢价被低估"。
按固定定义 `b(s) = F(s)/I(s) − 1`：

```text
R_F / R_I − 1 = (b(t) − b(c)) / (1 + b(c))
```

基差收窄 `b(t) < b(c)` 给出 `R_F < R_I`：期货**低估**指数涨幅，代理净值偏低，估算溢价**偏高**。
算例：`b(c) = 0.01`、`b(t) = 0.0095` → 相对误差 −4.9505bp；真实溢价 10% 时估算溢价偏高 5.4482bp。

改正符号后也不给出新的方向结论：那几个负值是美股时段端点样本，不是亚洲时点观测。
"亚洲方向为负""系统性低估""亚洲时点溢价被高估"都不写。

## P1 · 总误差与买入结论

**接受。** f237d46 第 9.3 节把跨日段（≤ 0.7bp）、期货段（中位约 3bp、P95 约 5bp）、舍入（0.5bp）并列在 10%—14% 的溢价背景下，
引出"总误差很小（小于 0.1 个百分点）、不会影响买入判断"的读法。不同口径的样本统计不能相加成总体 P95 或上界；
期货段未知时，总误差也未知。9.3 已删除，相关读法撤回。

另撤回"`b(c)` 每天精确已知"：研究序列用的是 Yahoo 五分钟线收盘，既不是正式指数收盘，也不是生产所用的结算锚点

## P2 · 端点错配

**接受，并已复现。** f237d46 按标签取期货与指数时间戳的交集，再取每天最后一个共同标签作收盘端点。Yahoo 五分钟线的标签是
区间起点，NDX 在 09-17 还多一条标签为 16:00 的收盘时刻记录，于是那天的"收盘"是 NQ 16:00—16:05 线（29737.25）配
NDX 16:00 记录（29446.98046875），其他日子则是 [15:55, 16:00] 的两条线。把 f237d46 的配对逻辑套在录制夹具上，
复现出 98.57bp，即旧证据中的 `last_close_basis_bp = 98.6`。

**修正（`qdii.core.futures_basis_research`，纯函数；日历调度在工具 I/O 层）：**

- 记录按时间结构分类：普通五分钟线（区间 [ts, ts+300]，观测时刻取区间终点）、指数收盘时刻记录（`SESSION_CLOSE_RECORD`，不进主序列）、
  接收时尚未结束的线（`PARTIAL_BAR`）、不在网格或不在现金会话内的记录（`UNKNOWN`）；值的质量另行判定（null、非数值、非有限、
  非正、同时间戳冲突）。不按价格远近猜记录类型。
- 主序列 `BAR_CLOSE_TO_FIRST_BAR_CLOSE`：前会话最后完整五分钟线收盘 → 下一会话首根五分钟线收盘。09-17 收盘期货价只能是 29744.50，
  NDX 是普通线 29442.1171875。
- NDX 收盘时刻记录只有与独立官方收盘（生产原始日志中的 Nasdaq 29446.98）在公布精度内一致，才标 `OFFICIAL_CLOSE`，
  并且只进单列的 `OFFICIAL_CLOSE_TO_FIRST_BAR_CLOSE` 诊断，配结束于收盘的期货线，不配 16:00—16:05 线。官方记录不足时该诊断为 `NO_DATA`。
- 会话来自现有 `CalendarProvider`（NASDAQ→XNYS），覆盖冬夏令时、提前收盘、节假日；日历不确定时不出样本。
  只在相邻预期会话端点齐全时成对，缺数的会话记为数据缺口，不会把周一到周三标成正常隔夜；零样本返回 `NO_DATA`，不再崩溃。

**测试：** `tests/unit/test_futures_basis_research.py`，夹具 `tests/fixtures/recorded/yahoo_basis_endpoints_20260917.json`
从两条已校验哈希的父响应原样抽取（带父响应 hash 与 msg_id）；合成序列在测试中标 synthetic。
把配对改回按标签（旧行为）会让 10 项测试失败。

- 输出固定 `asia_decision_error_status = UNIDENTIFIED`、`asia_decision_error_bound_bp = null`、`decision_grade = false`；
