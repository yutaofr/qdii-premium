## 逐项处理

### D1 · 旧行情停更后仍标可用

**修正（ADR-037）：** `evaluate_enav`（`src/qdii/core/enav.py:92`）独立检查以下各项，不继承相对比较的组准入：

| 条件 | 检查内容 | 不满足时 |
|---|---|---|
| 日历覆盖 | 截止日与成员锚点日期都在覆盖范围内 | CALENDAR_UNCERTAIN |
| 报价阶段 | 连续交易，或合格的收盘参考冻结快照 | SESSION_BOUNDARY |
| 时效（仅当前估算） | 按知识截止时刻：ETF 报价 ≤ 60 秒、期货 ≤ 60 秒、汇率 ≤ 120 秒 | TIME_SKEW / FX_STALE |

结果改为三态：

- **PROXY_ANCHOR**：当前可用的盘中代理估算。
- **REFERENCE**：收盘或午休参考快照上的估算，只作历史参考。
- **UNAVAILABLE**：给出原因。

`absolute_premium_available` 只在出现 PROXY_ANCHOR 时为真。页面把收盘参考估算以灰色标注"收盘参考估算（非当前）"，命令行加 `*` 并附说明。

**测试：**
- `test_d1_stale_quotes_at_cutoff_make_current_estimate_unavailable`：复现场景全部 UNAVAILABLE 且带 TIME_SKEW；日历未覆盖时全部带 CALENDAR_UNCERTAIN。
- `test_d1_estimate_does_not_inherit_relative_group_eligibility`：只有一只基金有行情时，相对比较 INELIGIBLE，该基金估算仍为 PROXY_ANCHOR。
- 参数化用例：截止时刻过期、日历、阶段各一条。
- 收盘参考夜间查看时为 REFERENCE。

### D2 · 唤醒后消耗旧轮询等待

**修正（ADR-038）：**

- **等待条件：** `_sleep_until_next`（`src/qdii/apps/collect.py:306`）改为单调钟或墙钟任一走过间隔即结束等待。macOS 睡眠时墙钟前进，唤醒后在一个等待分段（≤ 15 秒）内重新取数；墙钟回拨时仍由单调钟兜底。
- **缺口识别：** 每次构包后由 `input_gaps`（`src/qdii/pipeline/relative_state.py:441`）列出估算缺数的端点，冷启动时先算一次。可识别的缺口有三类：最近美股收盘的指数、净值日的中间价、基金净值。
- **缺口重试：** 缺数端点的等待上限改为 `max(120 秒, 失败退避)`（`GAP_RETRY_S`）。仍遵守退避、403/429 封禁和窗口约束。
- **不变的部分：** 其余端点保持原周期。

**测试：** `tests/unit/test_collector_wake.py`，驱动真实 `Collector._poll`、`Fetcher`、原始日志写入和模拟 HTTP。

| 用例 | 场景 | 断言 |
|---|---|---|
| `test_wake_next_day_five_minutes_before_close_refreshes_immediately` | 睡眠跨日，收盘前 5 分钟恢复 | 唤醒后 15 秒内再次请求 |
| `test_critical_input_gap_retries_soon_instead_of_hourly` | 首次请求失败且估算仍缺该输入 | 60—135 秒内重试，不再等 1 小时 |
| `test_without_gap_or_sleep_normal_interval_is_kept` | 无缺口、无睡眠 | 不额外请求 |

与四审一致：这是注入时钟模拟，不是真实 Mac 睡眠实验。真实唤醒行为在用户正常早晨使用时由事件日志核验（`SLEEP_OR_CLOCK_JUMP` 缺口之后的首次请求时间）。

### D3 · 没有真实成功样本

**新增 `tools/enav_evidence.py`。** 行情、净值、即期汇率来自生产原始日志；指数收盘与中间价来自 09-15 研究抓取（北京 15:23 收到，端点 ID 映射）。生成两个样本：

| 样本 | 截止（北京） | 性质 | 结果 | 独立复算 |
|---|---|---|---|---|
| AS_OF_REFERENCE | 09-15 15:30 | 所有输入的接收时间都不晚于截止，as-of 真实；收盘参考模式 | 5/5 REFERENCE | 5/5 一致 |
| BACKFILLED_CURRENT | 09-15 14:50 | 指数与中间价实际在截止后收到，接收时间被改写为 09:00，**只验证计算链，不代表当时已知信息** | 5/5 PROXY_ANCHOR | 5/5 一致 |

**独立复算方式：** 不调用任何 qdii 解析器或估值函数，按字段位置和 JSON 键直接读原始报文，用 Decimal 计算。取值来源与核对项：

- **价格：** 新浪第 3 位（最新价）或第 21 位（卖一价）。
- **N0：** 东方财富 `DWJZ`，并核对 `FSRQ` 与净值日一致。
- **I(a)、I(c)：** Nasdaq 按日期取 `close`，核对指数日 a 与美股收盘日 c。
- **X0：** CCPR 按日期取值。
- **F(t)、F(c)：** 新浪 hf_NQ 第 2、3、7 位。
- **X(t)：** CFETS 的 USD/CNY 买卖价。

分别复核估算净值（相对误差 < 1e-9）、溢价、指数日期和结算字段。

**以 513100 为例（as-of 样本）：**

| 项 | 取值 |
|---|---|
| 价格（收盘） | 2.196 |
| 已披露净值 N0（09-11） | 1.9831 |
| 净值日指数 I(a)（09-11） | 29368.44 |
| 最近美股收盘指数 I(c)（09-14） | 29127.16 |
| 期货 F(t)（北京 15:00:06） | 29047.500 |
| 昨结算 F(c) | 29152.250 |
| 中间价 X0（09-11） | 6.7743 |
| 即期汇率 X(t)（14:59:42） | 6.71315 |
| 估算净值 | 1.94205 |
| 估算溢价 | 13.08% |
| 基差 | 8.6bp |

五只估算溢价 9.54%—14.22%，高低次序与相对排名一致。摘要见 [evidence/enav-2026-09-15.json](evidence/enav-2026-09-15.json)，快照在仓库外证据目录。

**仍缺：** 生产窗口内实时收到、当场算出的成功样本。它将在用户首次正常早晨使用时产生，按冷启动场景核验，不会用研究样本替代。

### D4 · 代理假设尚未证实

- **外部依据：** 接受四审引用的 CME 官方说明：日结算按对应合约 15:59:30—16:00 ET 的成交加权均价确定。它只支持普通交易日的代理思路，不证明新浪字段的结算日与合约。
- **尝试获取带合约月份的历史结算：** 我只读访问了一次 CME 结算接口，返回 403，明示禁止自动访问。已停止，未重试、未绕过；该途径不可用。
- **现有数据的旁证（不作证明）：** 09-15 看到的昨结算 29152.25 落在 0.25 点格点上；它相对 09-14 NDX 收盘的基差为 8.6bp，与 9 月合约 4 天到期的持有成本量级相符。若是 12 月合约，基差应在 0.5% 以上。
- **后续核验：** 利用用户正常使用时顺带采到的行情，观察 9/18 九月合约到期前后昨结算与买卖价是否在同一时刻一起跳到新合约水平，以及基差是否随之从近零变为约 1% 量级。不需要夜间守机。未核实前保持现状。
- **页面措辞：** 统一为"盘中代理估算（结算日未验证）"，锚点说明写明"结算日与合约月份未经供应商证实"。
- **"实时"表述：** 新浪、CFETS 的供应商时间未经盘中验证，报告不使用"实时溢价"。

## 四审场景对照

| 场景 | 当前行为 | 状态 |
|---|---|---|
| 没有昨晚原始日志，收盘前首次启动 | 启动即请求所有端点；冷启动先算缺口，缺数端点每 120 秒重试；成功显示带质量说明的估算，失败列具体缺口 | 实现；实测待首次使用 |
| 前次运行后睡眠，次日收盘前才唤醒 | 墙钟判定间隔已过，一个等待分段内刷新 | 实现（模拟测试） |
| 短暂断网后恢复 | 失败按 5→15→30→60 秒退避后恢复；过期期间估算为 UNAVAILABLE（TIME_SKEW） | 实现 |
| 用户关闭电脑几天再使用 | 净值每次取最近 5 条（只需最新净值及前一日），指数取最近 30 天、中间价取最近 40 条，冷启动即补齐；原始日志回看 10 天 | 实现；未实测 |
| 美股休市、提前收盘、换月 | 休市与提前收盘由日历确定最近美股收盘日；换月语义未验证，只能靠基差异常筛查 | 部分 |
| 收盘/集合竞价阶段 | 非连续交易即收盘参考模式，价格口径为最新价，估算为 REFERENCE，页面标"非当前" | 实现 |
| 保存判断依据 | 页面按 bundle_id 导出所见输入包，包含全部估算输入与结果，可复算 | 实现 |
