## 2 用户价值与产品模式

用户先回答“同类五只里，当前买入哪只相对贵／便宜”，再回答“当前价格比估算经济价值贵多少”。两者数据依赖、可用性与误差分别表达。

| 模式 | 首版定位 | 依赖和输出 |
|---|---|---|
| R：相对估值参考 | 首版优先 | 已核验的各基金历史NAV／指数／FX锚点、基金事件及ETF价格；满足M0可分离条件时无需当前NQ和FX；显示相对价差，不能冒充绝对溢价 |
| E：绝对参考估算 | Phase 0条件启用 | 完整NQ及FX因子链；可以是有明确标签的代理或延迟参考；链不完整时对应数值为空 |
| V：经验证实时估算 | 后续数据达标升级 | 源身份、延迟、锚点和严格时效均达标；“实时”只描述时效，模型假设及误差继续单列 |
| L：后续增强 | 不阻断首版 | M1/M2、自动备源、PCF代理、经验区间、机会通知、深度成交估计、通用历史查询、日历热更新 |

R不是“无条件最便宜”：它依然受X₀错误、仓位差、费用、事件及异步报价影响。无差分误差依据时只给模型参考排序，不颁发“已确认最便宜”。至少两只基金满足条件才有成对比较；不合格基金明确退出，其余仍可比较。覆盖五只仍是首版接入目标，但单只资料缺失不堵塞全部功能。

E/V不会从免费接口取得基金“真实实时净值”。NAV、IOPV、E-NAV、A-NAV和ETF市场价格分别显示；A-NAV或IOPV不能代替申赎执行成本。费用、结算及额度完整的套利模拟不在首版范围。软件不自动下单、申赎、融资或承诺收益。

“免费”约束市场数据订阅成本，不承诺运行主机免费或上游永久开放。首版只服务个人；手机适配不等于默认开放公网。长期运行及可选远程访问见DS-10。

参考集思录的并列表格、净值日期、申赎信息与口径说明，不依赖其会员接口，不声称复刻内部公式。其站务及页面曾说明自估、IOPV与已披露净值的调整，因此与平台比较前必须核对日期和分母。[集思录站务说明](https://www.jisilu.cn/question/519230)、[QDII页面](https://www.jisilu.cn/data/qdii/)。

## 3 Phase 0：先验证，再确定ADD范围

时间盒为约1—2周，目标10个实际A股会话及对应美股收盘；节假日导致不足时报告有效样本数，不用自然天数冒充覆盖。期限结束必须选择产品路径，不无限延期等待免费实时源。当前结论：待执行；不将本次文档检查记为Phase 0完成。

| ID | 验证工作 | 必须交付的证据／判据 |
|---|---|---|
| P0-01 | 先制作录制回放工具 | 一段实采盘中会话与一组合成故障可离线回放；原始及合成数据分开；来源及接收时间可追溯 |
| P0-02 | NQ固定月份／序列身份 | 来源、真实合约或构造说明、price_type、tick、日期时区；仅“能识别大跳变”不足以支持V |
| P0-03 | 换月风险 | 取得实际或可核验历史换月证据；没有自然换月样本则报告缺口，夹具只能检验程序行为；固定月份方案可先避免盘中切换，不能宣称已验证连续代码 |
| P0-04 | 时效 | 按交易时段记录event_age、RTT、更新间隔、失效率、P50/P95/max；在公开延迟说明或可信同月份对照下评价真实延迟；无可靠对照则UNKNOWN，不能由短RTT升级为实时 |
| P0-05 | 各源c锚点与补采 | 每个拟启用源分别采集；故意漏掉至少一个收盘样本并从候选补采入口恢复。报告覆盖率及失败原因，无可用补采源明确no-go对应恢复能力 |
| P0-06 | 五基金资料与IOPV | 核验人民币单位NAV、股票日期、正式FX规则、事件；逐只记录IOPV候选字段及可用性，不要求五只都能取得IOPV |
| P0-07 | 历史经济验证 | 不依赖NQ，逐只比较日期／FX假设，优先≥120个区间，前60开发、后60样本外；样本不足或只有修订后数据如实报告 |
| P0-08 | 日历与运行资源 | 实测选定库的沪深／纳斯达克／NQ覆盖、跨年和提前收盘；确认夜间唤醒／常驻能力、时钟同步及手机访问方式；未获得资源能力不得承诺自动夜间捕获 |

Phase 0交付：源能力矩阵（每项PASS/FAIL/UNKNOWN）、会话及锚点覆盖报告、历史验证报告、录制回放入口、带原因的产品路径决定。不得仅提供候选URL清单。

**Go/no-go路径：**

1. **GO-R：** 至少两只基金具备VM-10要求的有效锚点与价格，相对规则及基础失败行为通过 → 进入R的ADD。其余基金继续显示缺失原因。
2. **GO-E：** 当前因子、同序列c锚点及连续性足以支持明确标签的参考估算 → E可加入ADD；未知合约连续性不能凭可见数值强行放行。缺补采源时可采用“漏采则禁用当天相应绝对链”的受限方案，并明确降低覆盖目标。
3. **GO-V-CANDIDATE：** 存在经身份核验的明确月份源，且有可靠依据确认无系统延迟，10个有效会话中V时效条件的可用覆盖比例达到预设初值95%，所需c锚点均取得或有效恢复，故意漏采测试通过 → 可规划V；这不是未来时效或模型误差保证。未达到就正式以参考版为产品定义。
4. **NO-GO-R/E：** 连历史FX／NAV锚点与价格都不足 → 不承诺实时估算或默认相对排序，只能显示已披露NAV对照并列出缺口，停止这两个功能的ADD，不用虚构参数填满表格。

GO-E不要求先完成V或全部自动恢复；GO-R不依赖GO-E。正式ADD依据实际结论和首版范围编写，本次不伪造go结论，也不在SRD中提前指定采集架构。

## 4 指标、排序与场景

默认首屏显示：代码／管理人、卖一及可见数量、相对模型价差及基准、比较状态、NAV日期；启用E/V后并列显示E-NAV及买入绝对估算溢价。最新成交比较通过显式切换启用，不与卖一混排。展开可查看全部因子、来源、年龄、模型／规则版本、退出比较原因。

| 指标 | 定义 | 展示要求 |
|---|---|---|
| 相对价差δij | (Pi/Bi)/(Pj/Bj)−1，Bi=N₀i/[I(ai)X₀i]；适用条件见VM-10 | 负值表示相对j便宜；基准变更不改变排序；非绝对溢价百分点 |
| 买入／卖出绝对估算溢价 | Pask/E-NAV−1；Pbid/E-NAV−1 | 缺侧则null；量和时效分别显示 |
| 最新成交绝对估算溢价 | Plast/E-NAV−1 | 可能不代表现在可执行价格 |
| 官方净值对照 | Plast/经有依据事件调整的NAV−1 | 始终显示NAV估值日期；累计净值不得作分母 |
| A-NAV对照 | 相同模型改用已核验正式估值FX | 不称真实申赎结算价格；未来定盘未知则null |
| 官方IOPV对照 | 价格/有效官方IOPV−1 | 未核验发布链或字段时不显示官方身份 |
| FX口径贡献 | P(1/NE−1/NA)，乘100为百分点 | 同时显示FX日期、类型；NA未知只可另列有标签假设情景 |

相对默认按S=Pi/Bi升序，在相同价格类型与合格因子组内比较。共用NQ失效不自动让R失效；基金自身资料失效会影响该基金的R与E。差异判断使用成对差分误差，不能因绝对误差区间重叠就否定相对差异，也不能自动假定所有误差抵消。

普通用户只看必要原因和时间，技术枚举在详情；正溢价、折价、相对价差分别命名，不单靠红绿。保留6位估值小数用于复算，展示溢价2位；排序使用未舍入值，但不把显示精度当作准确性。

## 6 运行与非功能要求

| ID | 首版要求 | 适用与验收 |

## 7 验收矩阵与追溯

## 9 实施顺序及ADD输入

1. Phase 0先交付录制回放和能力结论，日终历史验证同步进行；不等待精细模型或前端设计。
2. 依据GO-R实现五基金配置、最少有效子集比较、三态净值与秒级输入包、独立质量展示。
3. 依据GO-E增加绝对参考值、夜间c捕获、漏采状态与可行补采；未通过则正式交付R，不将“实时绝对值”留作默认承诺。
4. 只有后续源证据和适用测试满足时启用V，再按误差预算决定M1/M2、提醒及自动恢复投入。

ADD须给出与实际Phase 0结论相符的运行方式、单源／备源选择、保留策略、输入包与纯函数边界及恢复行为。SQLite／DuckDB、轮询／事件驱动、常驻／计划唤醒均是架构选择；本SRD不预定。新增指数保留配置扩展点，但首版验收仅覆盖五只纳指ETF。
